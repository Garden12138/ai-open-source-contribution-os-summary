# 桌面试用反馈 · 2026-11-25

## 从发现页打开和筛选 Issue

用户对整体 UI 的评价是“非常丑、低级、交互性差”。首排三张卡片里，语言、许可证、标签和 PR 统计挤在标题下方。左侧卡片的“73.9 分”断成两行，三张卡片的操作按钮也落在不同高度，横向比较机会很费劲。[发现页截图](images/feedback-2026-11-25/discovery.png)

最直接的交互问题是“点 Issue 都没反应”。卡片里最醒目的是 Issue 标题，但标题、仓库名和编号都是普通文字，真正的“查看 Issue”链接在卡片底部。用户没有指明点的是哪一处，底部链接在桌面端的实际表现仍待复现。改进后，用户应能一眼认出入口，用鼠标点击标题或用键盘激活它，在系统浏览器打开对应 Issue。

用户想像以前一样“只看少改动”。默认打开的“今日推荐”隐藏了筛选栏。现有入口要先切到“全部机会”，勾选“只看小改动”，再点“应用筛选”。这个入口应该在用户开始挑选 Issue 时就能找到。推荐卡也应把已有同题 PR 等会影响是否值得投入的信息放在显眼的位置。

页面写着“扫描完成 · 33 个候选，10 个推荐”，用户实际只数到 **21 条**。当天的扫描记录给出了从搜索到推荐的三个数量。

| 数量 | 本次扫描记录 |
| ---: | --- |
| 33 | 搜索去重后的候选，全部完成评估 |
| 23 | 通过筛选。另有 10 条因系统未识别到仓库许可证而被排除 |
| 10 | 从合格候选中选入“今日推荐” |

当时截图选中“今日推荐”，没有记录用户数出 21 条时的视图、筛选条件和完整列表。本机“全部机会”按无筛选条件查询得到 23 条，当时的 2 条差额仍待复现。扫描摘要应显示“找到 33 条，符合条件 23 条，今日推荐 10 条”，列表另行显示当前筛选下的总数和已展示数，让用户能在同一视图核对。

## 任务首轮的答复

用户进入任务想知道 Issue 描述了什么问题，以及 Agent 打算怎么修。首屏先后展示准备工作区的通知、多条“Agent 活动”和长命令。Agent 先说会阅读材料，随后只报告已有同题 PR、工作树干净、未运行测试。用户主动追问后才看到问题与方案，仍觉得答复不够清楚。后续多轮对话则被评价为“挺流畅”。[任务首屏](images/feedback-2026-11-25/task-start.png) · [首轮结束](images/feedback-2026-11-25/task-first-reply.png) · [追问后的答复](images/feedback-2026-11-25/task-follow-up.png)

首轮结束时，用户应能直接读到问题如何触发、影响谁、建议怎么改和怎么验证。遇到已有 PR，也要说明它覆盖了哪部分、状态取自何时、是否值得继续。准备状态和工具记录可以展开查看，首屏应优先留给这个判断。
