# 02 · 产品需求规格（v2）

## 1. 定位

**ContribOS v2 — 本地运行的开源贡献副驾驶。** 帮一个开发者每天发现值得做的
GitHub Issue，并在一个对话里调度编码 Agent 完成实现（陌生仓库在沙箱中执行），最后由用户确认
发布为 Draft PR，持续跟踪结果。

- 用户：单人，本机使用（macOS 为主，Linux 次之）。
- 仓库范围：GitHub 公开仓库；优先 Python、TypeScript/JavaScript，其他语言"能跑就行"，不做专门适配。
- 编码 Agent：通过 ACP 调度本机已有的 Codex、Cursor、Antigravity；后续接入 OpenCode、OpenHands 等开源 Agent，
  并可通过它们使用 xcli、DeepSeek 等模型。平台不自研 Agent。
- 执行隔离：陌生仓库默认在沙箱（Docker Sandboxes microVM，备选自管容器）中执行；
  自己的仓库或明确信任的仓库可以选择本机直跑。
- 形态：**桌面应用 ContribOS.app**（macOS 优先，Linux 次之）。常驻菜单栏，关闭窗口后任务继续在后台运行，
  需要你处理时发系统通知。开发调试时也可以在浏览器里打开同一套界面。

## 2. 核心旅程

### J1 发现机会

1. 首页"今日推荐"：按规则评分选出的 10 个 Issue（3 赏金 / 3 高影响 / 2 技术匹配 / 2 战略），
   每条显示总分、七维分解、风险原因、仓库信息、是否已有关联 PR。
2. "全部机会"列表：筛选（语言、标签、有无赏金、只看小改动）、排序、收藏 / 忽略。
3. "立即扫描"：后台扫描，页面显示进度；也支持每日定时扫描。
4. 任意入口粘贴 Issue 链接 → 直接进入 J2（不要求先出现在推荐里）。

### J2 发起贡献任务

1. 在机会详情点"开始贡献"（或粘贴链接），在弹出的面板中确认两项（都有默认值）：
   - **Agent**：Codex / Cursor / Antigravity 等，显示各自的安装和登录状态；
   - **隔离级别**：仓库 owner 不在可信列表时默认"沙箱"；选"本机直跑"需要勾选"我信任这个仓库"并确认风险提示。
2. 平台创建任务：拉取 Issue 正文和评论快照、检查是否已有关联 PR / 已被分配、
   准备执行环境（沙箱或本机独立工作区）并克隆仓库默认分支。页面实时显示准备进度。
3. 准备完成后，Agent 自动开始第一轮：阅读 Issue、CONTRIBUTING、相关代码，
   给出**可行性评估和实现方案**，然后停下来等用户回复。

### J3 对话贡献（核心）

体验对标 Codex / Cursor 的 Agent 对话：

- 用户发消息 → Agent 开始一轮工作，过程流式呈现：思考摘要、执行的命令及输出、
  修改的文件、待办清单进度、最后的文字总结。
- **运行中可以发消息**：输入框保持可用；默认排队，当前这一轮结束后自动发送；
  也可以选"打断并发送"，立即停止当前轮并发送新消息。
- **随时停止**：停止按钮中断当前轮，已做的修改保留在工作区。
- **随时继续**：任何原因停下（用户停止、模型限流、网络断开、服务重启、Agent 进程或沙箱重启）后，
  发送"继续"或点"继续"按钮即可在同一会话上接着干，**不需要重新审批**。
- **权限与提问**：本机直跑时，Agent 请求超出其默认权限的操作会以卡片出现，用户点允许或拒绝；
  Agent 提出带选项的问题时显示为提问卡片，可点选或自填。沙箱模式下权限请求自动允许。
- **不用盯着看**：关掉窗口任务照常进行；Agent 做完一轮、需要你处理权限或回答、出错停下时，
  会收到系统通知，点击通知直接回到该任务。菜单栏图标显示运行中的任务数和待处理请求数。
- 快捷短语（只是预填消息，不是特殊动作）："按这个方案开始实现"、"跑一下相关测试"、
  "自查一遍改动"、"缩小改动范围"、"同步上游最新代码"。
- 右侧面板：
  - **改动**：实时 diff（文件列表 + 逐文件差异），随 Agent 修改自动刷新。
  - **Issue**：任务创建时的 Issue 快照，可手动刷新。
  - **审查**：一键让另一家 Agent（例如 Codex 实现、Cursor 审查；不可用时用同一 Agent 的新会话，
    不继承对话）审阅当前改动，结果以卡片显示；用户可以说"按审查意见改"。
  - **用量**：本任务 token 用量和耗时。

### J4 发布 Draft PR（唯一强制确认点）

1. 用户点"准备 PR"。
2. Agent 按仓库的 PR 模板和贡献规范生成英文标题、正文、提交信息；平台在宿主侧
   生成**发布预览**：
   - 目标仓库、基线提交、Fork、分支名、单个提交（作者信息来自设置）；
   - 完整 diff 和统计；PR 标题与正文（可直接编辑）；
   - 检查项：Issue 是否仍为 open、是否出现新的关联 PR、上游默认分支领先多少提交、
     是否改了 CI 工作流、改动规模、是否运行过测试、审查是否针对当前改动。
3. 用户点"确认发布 Draft PR" → 平台创建/复用 Fork、推送分支、创建 Draft PR，
   回复中直接给出 PR 链接。
4. 预览之后若工作区又有修改，原预览作废，需要重新生成预览（只这一处"失效"规则）。

### J5 跟进与履历

1. 已发布任务自动定期刷新 PR 状态：open/draft/merged/closed、审查结论、评论数、CI 状态。
2. 维护者提了修改意见：用户在同一任务对话里说"处理 review 意见"，平台把评论带入上下文，
   Agent 修改后再走一次 J4（追加提交，快进推送，不 force-push）。
3. 可选动作（各自单独确认）：更新 PR 标题/正文、标记 Ready for review。
4. "贡献记录"页：按月统计已提交/已合并 PR，热力图，按仓库/语言分布，赏金任务单独标记。

## 3. 功能清单与优先级

| 编号 | 功能 | 优先级 |
| --- | --- | --- |
| F1 | 规则发现、评分、每日推荐、扫描进度、收藏/忽略 | MVP |
| F2 | 粘贴 Issue 链接创建任务 | MVP |
| F3 | 分级执行环境：沙箱（Docker Sandboxes，备选自管容器）与本机直跑；可信 owner 列表 | MVP |
| F4 | 对话：流式事件、排队/打断发送、停止、继续、权限与提问卡片、快捷短语 | MVP |
| F5 | 改动面板（实时 diff，由平台计算） | MVP |
| F6 | 发布预览 + 单次确认 + Draft PR | MVP |
| F7 | 故障自动恢复（限流/网络/服务重启/Agent 进程或沙箱退出） | MVP |
| F8 | 设置与自检（各 Agent 安装与登录、沙箱后端、GitHub 登录、默认 Agent、审查 Agent） | MVP |
| F9 | 独立审查（默认由另一家 Agent 审阅当前改动） | MVP |
| F10 | 多 Agent 接入（经 ACP）：Codex、Cursor、Antigravity | MVP |
| F11 | 沙箱出网策略：默认拒绝，放行 GitHub、包仓库和模型端点；禁止访问宿主和私网 | MVP（陌生仓库日常使用前必须完成） |
| F12 | 桌面应用：主窗口、菜单栏常驻、系统通知、关窗不打断任务、退出保护、单实例、开机启动 | MVP |
| F13 | PR 状态跟踪、贡献记录页 | v1 |
| F14 | 处理 review 意见并追加提交 | v1 |
| F15 | 更新 PR 文案、标记 Ready for review（单独确认） | v1 |
| F16 | 旧数据导入（机会、偏好、已发布 PR） | v1 |
| F17 | 开源 Agent（OpenCode、OpenHands 等）+ 自选模型（xcli、DeepSeek） | v1 |
| F18 | 任务中途换 Agent 继续（新会话 + 回顾 + 当前改动） | v1 |
| F19 | 更多机会来源（Algora 等赏金平台）、AI 辅助排序；应用签名与公证、自动更新；从浏览器一键把 Issue 发送到应用 | 后续 |

## 4. 对话交互规范

| 元素 | 规则 |
| --- | --- |
| 用户消息 | Agent 空闲时开启新一轮；Agent 运行中默认排队，可选"打断并发送" |
| Agent 文字 | Markdown 流式渲染；一轮结束时有一段总结 |
| 活动卡片 | 命令（命令行、退出码、输出末尾，可展开）、文件修改（路径、增删行数）、待办清单、思考摘要（默认折叠）、上下文压缩提示 |
| 系统提示 | 准备进度、自动重试（"模型限流，30 秒后自动重试 1/3"）、错误原因 + 继续按钮 |
| 停止 | 中断当前轮；工作区保留；状态变为空闲 |
| 继续 | 在同一会话开启新一轮，默认提示词"从上次中断处继续"；会话无法恢复时自动新建会话并附上回顾 |
| 权限/提问卡片 | 显示请求的工具、命令或问题；点击后才应答；Agent 进程重启后旧卡片显示"已失效" |
| 刷新/关窗/断网 | 界面重连后从最后一个事件继续接收，不丢消息，不影响后台 |
| 系统通知 | 窗口不在前台时：一轮结束、需要处理权限或回答、出错停下、发布结果、每日推荐就绪；可按类型关闭 |
| 退出应用 | 有运行中的任务时先确认；确认后安全停止，下次打开可"继续" |
| 授权 | 聊天文字、Agent 输出都**不是**授权；唯一的外部写入口是发布面板上的确认按钮 |

第一轮的默认行为是"评估 + 方案 + 等待回复"。用户可以在设置里改为"直接实现"。
方案只是一条消息，没有版本、锁定和审批对象。

## 5. 人工确认点

| 动作 | 是否需要确认 | 方式 |
| --- | --- | --- |
| 读代码、改代码、装依赖、跑测试（沙箱内） | 否 | Agent 自主 |
| 本机直跑时 Agent 请求超出默认权限的操作 | 是 | 对话中的权限卡片 |
| 对不在可信列表的仓库选择本机直跑 | 是 | 新建任务时勾选并确认风险 |
| 有任务运行时退出应用 | 是 | 退出确认框 |
| 是否按方案实施 | 软确认（默认等待回复，可关闭） | 对话 |
| 创建 Fork、推送分支、创建 Draft PR | **是** | 发布面板按钮，绑定预览哈希 |
| 追加提交推送、更新 PR 文案、标记 Ready | **是** | 各自预览 + 按钮 |
| 删除任务（销毁容器与工作区） | 是 | 普通确认框 |

## 6. 非目标

- 托管 SaaS、多用户、团队协作、支付托管。
- 自动认领 Issue、自动评论、自动合并、force-push、删除远程分支。
- 自动签署 CLA（只展示链接，用户自行处理）。
- 平台自研编码 Agent、自研依赖推导引擎、断网复现验证。
- 为特定项目写适配代码；为单个 Agent 写平行的业务流程（差异只放在 Agent 配置里）。
- 操控桌面 GUI 应用（Cursor.app、Antigravity.app 等）；只通过各家 CLI 的 ACP 接口接入。

## 7. 验收标准

### 7.1 产品级验收（真实环境）

在 **3 个真实、未解决的 Issue**（至少 1 个 Python、1 个 TypeScript）上，只通过桌面应用（从 Finder 启动）完成：
发现/粘贴 → 对话 → 改动 → 测试 → 审查 → 发布 Draft PR。每个任务满足：

- 用户操作只包括：发起任务、在对话中回复（含确认方案、权限卡片）、确认发布；
- 不需要外部 Codex/终端介入修平台；
- 期间至少人为制造一次中断（退出应用或杀掉 Agent 进程），能通过"继续"恢复；
- 至少一次在关闭主窗口的情况下收到"需要处理"或"一轮结束"的系统通知，点击后回到该任务；
- 从发起到 Draft PR 不超过 60 分钟（不含用户思考时间）。

三个任务合起来还要满足：至少 1 个在沙箱中完成；至少用到 2 家不同的 Agent（实现或审查均可）。

首次验收建议把 PR 发到自己的测试仓库（Fork 一个小项目），确认流程无误后再对上游发布。

### 7.2 观测指标（任务详情和记录页可见）

- 每个任务：轮数、工具调用数、token 用量、耗时、自动重试次数、中断次数与恢复结果。
- 全局：任务 → Draft PR 转化率、Draft PR → 合并率。
