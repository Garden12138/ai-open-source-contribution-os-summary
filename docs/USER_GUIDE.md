# 产品使用手册

## 项目用途与当前范围

工作台帮助个人寻找值得投入的 GitHub Issue，并保留评估、方案、执行与审查记录。它不保证赏金、贡献接收或代码自动正确。

目前最适合体验：发现推荐、评分解释、偏好、候选、分析报告及任务历史。默认离线模式有一条预设的完整结果链路；真实 AI 对话、Coding 和 GitHub 发布需要额外配置，尚有验收限制。

## 第一次试用

安装依赖后：

```bash
./scripts/local-start.sh
./scripts/local-smoke.sh
open http://127.0.0.1:18765
```

页面顶部显示“离线试用”；终端和 `.local-demo/last-smoke.json` 提供精确任务、执行和 Review ID。

1. “发现机会”中打开带“离线样例”的 Issue，查看七维评分与风险原因。
2. 设置贡献目标、语言、每周投入，然后“保存并查看推荐”。偏好不会覆盖原规则分。
3. 将 Issue 加入“我的候选”，在该视图继续查看或比较。
4. 在“贡献概览”或侧栏“最近任务”打开 smoke 样例，查看方案和执行历史。
5. 用终端输出的 result_url 查看执行、Artifact 清单与 Review。它们是 Fake 结果，不能当作真实仓库测试成功。

结束后 `./scripts/local-stop.sh`。再次启动保留历史；再次 smoke 新增另一条样例。

## 发现与筛选 Issue

真实模式按 [运行手册](LOCAL_SETUP.md) 启动独立只读发现实例。点击“立即扫描新机会”，Worker 处理持久 Job；按界面查看进度、取消或重试失败任务。

系统先过滤归档、已分配、许可不明、描述不足、不活跃仓库，再评估奖励可信度、接受概率、技术匹配、影响力、清晰度、竞争与学习价值。每日配额 3 赏金、3 高影响、2 技术匹配、2 战略；不足则确定性补位。

“只看小改动”是初筛，实际范围仍需读代码确认。“AI 筛选候选”在 Provider 可用时启用，真实模式可能计费；离线模式仅返回 Fake 数据。加入候选、忽略和提醒都是本地行为，不会认领或评论 GitHub Issue。

## 查看分析

打开机会详情，Provider 可用时发起分析，等待完成后查看项目介绍、需求概括、投入、风险与建议。报告支持查看、下载、版本比较。它绑定精确 Snapshot；旧报告不会冒充新扫描结论。

smoke 已生成 Fake 分析；也可在发现页运行 Fake 筛选。真实只读模式默认 ANALYSIS_PROVIDER=none，只有规则结果。

## 创建任务与方案

真实模式下，在详情或“我的候选”点击“开始对话制定方案”；已有任务从“最近任务”继续。无需先做深度报告，系统会绑定精确快照。

描述目标、回答必要问题、检查可编辑方案。方案包含可写路径、步骤和验证命令；修改产生新版本。执行前检查 base、路径和预算，再做新的精确确认。旧批准、聊天和 AI 建议不能代替确认。

**离线模式不提供真实自主规划对话。** local-smoke.sh 通过 API 保存预设方案并批准合成 base，只演示后续数据流。API 请求形状可在 `http://127.0.0.1:18765/docs` 查看。

## Coding、Verify 与 Review

真实任务需要独立 Gateway、Provider Worker、Sandbox Worker 和固定摘要镜像。仓库读取、依赖准备、Coding、测试均应处于规定隔离边界，不能直接在宿主执行外来代码。

任务详情展示差异、测试摘要、Artifact 与 Review。失败需区分基线问题、环境不支持、模型失败与新增回归；改变输入后重新批准，不能沿用旧确认。

离线样例采用预设 Patch、模拟 Verify 和 Fake reviewer。它验证应用与持久化链路，不证明 AI 编码质量、真实测试成功或独立 AI 审查。

## PR 工作流

已有发布预览、一次性确认、Draft PR、文案更新、ready 与 CLA 专项确认实现。离线 PUBLISHER_MODE=none，不会产生远程 PR。真实发布需要专用账号、测试仓库、独立 Publisher 和新的精确人工确认。本轮未做业务 Fork/Push/PR、CLA 或 ready 操作。

## 历史与模型设置

“贡献概览”、侧栏和任务详情保存方案、执行、测试、审查与事件，刷新和重启后仍可查询。Job succeeded 不表示整个贡献完成。

“设置”→“模型设置”管理连接、模型和四阶段默认。离线可以打开页面，但真实凭据保存和连接测试不可用。真实模型请遵循 [正式配置](LOCAL_SETUP.md#切换真实-ai-模型)，通过加密设置流程输入 API Key，不能粘贴进聊天；更换模型不会重置旧任务预算或恢复终止授权。

## 失败处理与未支持功能

| 情况 | 处理 |
| --- | --- |
| 操作持续排队 | 检查对应 Worker、数据库和私有日志 |
| 旧报告/方案 stale | 取当前快照，建立新版本并重新检查批准 |
| Provider 不可达/缺密钥 | 检查 Gateway readiness，避免反复消费额度；可回到独立 Fake 实例 |
| 环境或依赖失败 | 查看具体原因；不能在宿主绕过隔离 |
| Review 阻断 | 检查差异和失败结果，按有界修复或新方案处理 |
| 发布结果未知 | 保留 outbox，先核对远程，不盲目重发 |

不能声称已可用：陌生 Issue 稳定全自动 Coding、未经验证的 Linux 原生 Docker、容器 xcli Host Bridge、真实 Gateway 事故恢复、自动 Merge/评论/认领、SaaS 多用户和支付托管。Plan16 不可恢复，本轮未创建新付费 Plan。
