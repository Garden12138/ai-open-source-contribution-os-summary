# Native Read-Only Batch Scheduler v1

本次用户明确授权修正Plan12的超量只读批次契约。原历史文件中的“禁止自动分批”
仍描述当时策略；当前新协议只允许完整验证后的5–8个`read_file`分成4+余数。
其他超量组成和超过8个调用仍整批拒绝，`Decision.calls`与Checkpoint.pending_calls
的4-call上限完全保留。新策略纳入原生transport hash，仅适用于新的精确授权。
Plan11缺失调用仍为unavailable，Plan12终态与原审批不恢复。

原始安全调用信封仍在解析之前独立提交。解析器验证每个调用的类型、原始ID唯一性、
参数JSON/schema及路径语法；新增`NativeReadBatch`是提案，不是扩大后的执行Decision。
入队前再次核验信封、模型Job、Binding与所有参数/顺序，核对原沙箱策略并预留全部读取
次数。原始批次最多8个调用。输出容量用每页最大JSON转义字节和有界元数据保守校验，
结果仍按真实字节计费，读取预留不退还，失败的旧模型预留不变。

原始批次Artifact保存完整验证后的调用、原始响应引用、Binding/source/policy hash、
读取预留及两个确定性子批次。首次工具Job是整批OCI预检：同一固定归档/快照视图中，
检查所有路径、符号链接、文件hash、大小及UTF-8字节offset。预检不向模型输出文件正文，
不执行任何应用工具调用。任一位置失败，全部读取调用保持未派发；预算预留保留。

首次归档的内容地址和文件库存hash是两种不同标识。预检保存归档Binding与输入hash，
用OCI扫描证明canonical source hash；只有归档起点或与当前源码相同的视图才准入。
之后所有子批次、调用、回执、聚合、Checkpoint均绑定同一canonical hash。
快照来源改变、归档损坏、伪造预检或返回不同源码hash都阻断，不使用过期回执。

预检成功后才记录第一个子批次开始。每个子批次独立标识、起始Checkpoint及结果Artifact，
所有调用仍采用原有单Job租约、幂等ID和CAS事务。第一子批次完成后，同事务记录真实回执、
结果与下一子批次Checkpoint；不会回到model状态。只有整个原始批次结束才按原始顺序
提供下一轮反馈。精确重复优先复用，仍按请求计入已预留读取数；合法分页正常执行。

无进展按原始模型回合计算，子批次边界不单独重置计数。所有读取成功只表示取得证据，
不会把Coding、Verify或Review标为完成。模型反馈保留全部回执引用，正文按现有32000
输入边界缩小，next_offset始终按实际内联UTF-8字节计算，原始完整回执内容寻址保留。

中途任何只读调用失败都停止后续调用。已返回的真实回执、未派发调用和结果未知的已启动
调用分别保留，绝不把未知副作用写成“整批未执行”。未知结果只阻断，不隐式重发；
已提交调用在Worker进程重启后不重复执行。用户暂停、取消、过期授权、时间/预算耗尽
仍受现有状态机约束，不创建额外模型Decision或预算。

## 持久化与恢复

新增迁移`0044_native_read_batches`只添加Journal准入/生命周期约束，不改业务表或旧行。
旧Journal、Checkpoint和Artifact保持可读。新事件仍用`agent-runtime-v2`外层信封，
批次、预检、子批次和汇总Artifact分别有自己的版本；不把Artifact版本覆盖Journal版本。

升级前必须确认无活动Job，在原Linux业务容器用SQLite online backup保存一致副本，
保留旧事件/Artifact/预算与全部业务表hash。使用同一卷和原五个角色、安全/资源/网络/
挂载/凭据配置部署；只允许追加0044迁移记录。新协议不自动恢复任何旧终态。

恢复必须先排空写入者，导出并保留升级后批次、回执、未知结果及费用记录，再恢复配套
数据库、Artifact与代码备份；核验integrity、FK和旧链。不能删除迁移记录/批次事件、
退还预留、原地修改Checkpoint，或用重发付费请求重建丢失响应。

本轮只离线重放及OCI测试，不创建Plan13或新的付费任务，不Push或PR。
独立真实模型预览在离线验收完成后生成，新的有界预算和新授权必须由人类确认。
