# 04. Acceptance Matrix

## 1. 验收原则

分为单元测试、集成测试、真实模型测试和真实 Issue 端到端测试。前三层通过不代表第四层通过。

## 2. 功能验收

| ID | 内容 | 通过标准 |
|---|---|---|
| H-01 | Progress Ledger | 重启后状态与证据一致 |
| H-02 | 阶段迁移 | 非法迁移被拒绝并留痕 |
| H-03 | 精确重复读取 | 同参数、同源码 Hash 不重复执行 |
| H-04 | 分页读取 | 不同 offset 正常读取 |
| H-05 | 源码变化后重读 | 新 Hash 不复用旧结果 |
| H-06 | 无进展纠偏 | 达阈值发送一次有效纠偏 |
| H-07 | 无进展暂停 | 纠偏无效后暂停，不耗尽全部预算 |
| H-08 | Checkpoint 恢复 | 不重复执行已完成副作用 |
| H-09 | Tool Call 身份 | 每个结果关联唯一原始调用 |
| H-10 | 5-call 只读批次 | 原始信封先持久化，整批零执行拒绝并有限纠偏；禁止自动分批 |
| H-11 | 混合写入超量批次 | 不发生未经批准的部分写入 |
| H-12 | Patch 授权 | 计划外路径写入被拒绝 |
| H-13 | Verify Hash | 旧源码测试不能证明新源码通过 |
| H-14 | Repair 上限 | 达上限后明确阻塞 |
| H-15 | 独立 Review | 使用真实 Diff 和 Verify 证据 |
| H-16 | 完成门禁 | 缺 Patch、Verify 或 Review 时不可交付 |

## 3. Plan11 回归

必须覆盖 39 次读取涉及的 6 个路径、33 次 offset=0 重复请求、两次 5-call 超量批次和最终预算阻塞。

通过标准：

1. 精确重复读取不再重复执行底层读取。
2. 不同 offset 的分页读取仍可执行。
3. 源码 Hash 变化后允许重读。
4. 模型收到已有证据提示。
5. 超量批次有确定策略和有限恢复。
6. 不通过放宽写入权限解决协议问题。
7. 防重复机制不阻止合法调查。
