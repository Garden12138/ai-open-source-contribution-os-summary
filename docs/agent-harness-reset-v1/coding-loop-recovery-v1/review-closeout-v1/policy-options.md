# 6/8 与跨模块投影的对比方案

这里是供选择的设计，不是新增执行授权或已实现功能。当前生产源码仍保持 6 轮纠偏、8 轮无有效 Patch 后停止，工作集仍为最近四文件。总模型 24、读取 64、写入 24、检查 6、协议纠偏/Provider 重试/修复各 2、输入 200000、输出 32000、证据 500000 字节、1800 秒、单次输入界限 32000/输出 4096 以及独立 Review/沙箱原上限均不增加。

| 候选 | 第 8 轮新证据后的结果 | 安全与费用影响 | 建议 |
| --- | --- | --- | --- |
| A 保持无条件 6/8 | 第 9 次不调用，最后新源码可能从未进入模型 Prompt | 最紧成本边界；已证实有可实施但无决策机会的误停 | 本轮保留实现，作为对比基线；整体不部署 |
| B 一次有证据交接 | 仅当第 8 轮合法只读工具新增了当前源码且尚未送达，允许一次交接决策，然后成功 Patch 或停止 | 相对 A 最多增加一次可能调用，即使仍在原 24 上限内也会增加最大可能费用；需要精确协议冻结和另行授权 | 优先评审；本轮未实现 |
| C 只有有 Patch 后的 Verify/Review 阶段豁免该守卫 | 不解决首次 Patch 前的末轮新证据问题 | 正常 6→Patch、7→Verify、8→finish 本已通过；全面阶段豁免可能多花调查额度 | 单独采用不能解决本次反例，不建议扩大豁免 |
| D 每次新读取都清零无 Patch 计数 | 可继续读到总预算耗尽 | 回到“读取新颖性冒充 Coding 推进”，容易耗尽输入/输出/证据预算 | 不采用 |

B 必须同时满足的约束：

1. 新增字节由成功、当前工作区、文件 Hash 和真实工具回执证明，且原来没有送达；不能用 Plan/历史元数据或重复恢复触发。平台不声称能从文本推断“关键证据”的语义重要性。
   交接请求本身必须实际内联这些新字节并保留原始引用，否则不授予例外；不能仅因有一个可恢复 Hash 就花费额外调用。仍受四文件与 32000 界限约束，可能需要调整当前片段分配，但不能扩大容量。
2. 没有未知模型/工具结果、活动子批次、哈希不匹配或非法审批；必须先完成原始批次。身份不匹配仍拒绝，未知操作仍停止。
3. 每个未应用有效 Patch 的调查区间至多一次，崩溃后必须能从 CAS Journal 证明已消耗；不能靠重启、Provider 重试、新页面或新 Plan 复用来再次获得。
4. 只使用原剩余额度，派发前重新校验输入/输出/时间及全部维度。余额不足直接停止；截断仍保留实测用量和原预留，不退历史费用。
5. 交接不是强制 Patch：证据不够可报告具体缺失或 blocker。交接后继续读取不会无限延长；终态不得恢复，不自动另起付费轮次。

“内部允许 9 次但总数还是 24”仍然改变当前 8 次停止合同；不得只改数字或实现成默认例外。采用 B 后需要新的离线失败/恢复注入，以及独立代码审查和新的精确冻结，随后才谈真实模型验收。

## 四文件工作集

候选一：在两个已观察模块间提供最小覆盖（例如各至少一个片段，余下两格按当前显式读取与近期度分配）。候选二：先选可用但尚未送达的文件，再按近期度打破并列。二者都只取已读 Artifact 精确字节，不新增自动读取，不扩大四文件或 32000 输入界限。

最小覆盖可避免单模块持续占满，但会压缩当前聚焦模块的片段数；“未送达优先”会改善覆盖，却可能把当前修改所需锚点挤出新请求。历史送达不能当作模型跨请求记忆。模块应从真实路径/冻结任务上下文确定，不能在通用平台硬编码 web/extension 名称或平台编造任务摘要。

建议先比较候选一与原近期排序在保存 Plan15、两个读取顺序、缺失模块分页、修复后 Verify/Review 场景中的实际当前内联覆盖，再选择策略。任何选择都要显式反映到协议 Hash，保留原始回执和完整历史恢复，不能把“有恢复入口”当成该源码已经送达。本轮仅交付对比，不改选择算法。
