# Contribution Studio

原生 HTML/CSS/JavaScript 工作台，不引入前端框架。侧栏包括发现机会、我的候选、
贡献概览、最近任务、模型设置、推荐偏好和提醒；浅色为默认，可切换深色。

## 日常使用

1. 发现页和候选页使用紧凑卡片。点击卡片打开详情，再查看 Issue 原文、规则评分、
   AI 报告和贡献入口。候选比较、提醒和移出候选功能保留。
2. 打开贡献任务直接进入对话。方案生成后点击对话里的方案卡片编辑；有执行记录时，
   点击“执行记录”卡片查看代码、测试与审查。详情内有“返回对话”，不再常驻三个
   切换按钮。桌面两栏独立滚动；窄屏按需展开详情。
3. 打开任务本身不调用模型。发送消息才启动持久规划 Job；支持 Ctrl/Cmd+Enter，
   输入法选词时不会误发。切换任务保留当前页面内的消息草稿和方案编辑；刷新前
   提示未保存内容。草稿不写入浏览器持久存储，刷新后不能保证恢复。
4. 方案保存生成子版本；确认精确方案后才执行。模型回复不构成执行或发布授权。
   输入框运行时用“停止”替代发送；“更多”收纳重新读取上游代码、任务模型设置，
   以及执行结束后的返回方案讨论。发布确认后不提供停止或返回规划操作。
   修改目标和方案直接在对话里说明；查看卡片不调用模型，也不授权执行。
   重读代码、失败后重新发送消息和查看版本差异仍使用原工作流。

完整执行、隔离和发布边界见 [贡献方案工作台](contribution-workbench.md)。

## 查看代码变更

执行生成修改产物后，对话自动出现文件摘要，例如“已修改 3 个文件 · +28 / −9”。
每个文件列出新增、修改或删除状态及增删行数；点击文件进入详情，定位到该文件。
详情用红绿差异显示原行号、新行号、增删标记和上下文，支持折叠、复制路径、查看
原始 diff，以及返回对话。测试和审查状态独立显示，已有修改不代表验证通过。

摘要每次展开 5 个文件；代码默认加载前 300 行，可继续加载。状态轮询不重置展开
或滚动位置。二进制／未收录内容只显示文件变化，不估算行数；权限变化单独标注。
无法解析的 diff 保留原文并标记行数不可用；读取或完整性校验失败不会显示为零修改。

数据复用同一执行、同一 Implement manifest 的 `unified-diff` 和 `file-inventory`，
经现有只读 API 校验后展示。没有数据库迁移、模型调用或第三方写入；只展示当前
执行相对冻结基线的修改，不提供逐次编辑回放或跨执行比较。本次源码改动尚未部署。

离线验证：`node --test tests/execution_changes.test.mjs`。启动下文的临时浏览器服务后，
运行 `node tests/execution_changes_browser.mjs` 验证摘要、定位、轮询、错误恢复与布局。
可设置 `PLAYWRIGHT_MODULE` 指向已安装的 Playwright，或设置
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向已安装的 Chromium 可执行文件。截图写入系统
临时目录；这些模拟展示结果不构成真实沙箱或跨平台验收证据。

## 一次性部署配置

现有 Compose `nvidia` Profile 现在承载通用 Provider Worker 和 Model Gateway，
兼容原 NVIDIA 部署，也可只使用自定义 OpenAI 兼容连接，不要求 NVIDIA API Key。
保留既有 `MODEL_GATEWAY_SIGNING_KEY`；另外生成一个独立、至少 64 位十六进制的
`MODEL_GATEWAY_MANAGEMENT_KEY`，只交给 API 和 Gateway，不得复用任务签名密钥。
将值保存到私有部署配置，不要提交到 Git、截图或日志。

Compose 已设置：

- API 通过专用内部 `model-management` 网络管理密钥，不接触明文模型密钥。
- Provider Worker 仅持有短时任务令牌签名，不拥有管理密钥、真实模型密钥或 Docker socket。
- Gateway 将凭证保存到独立 `contribos-model-secrets` 卷 `/data/model-secrets`；
  API、业务数据卷、Sandbox 和 Publisher 不挂载该卷。
- 自定义连接需要 Gateway 能直连公共 HTTPS 服务。`NVIDIA_HTTPS_PROXY` 仅用于原
  NVIDIA 传输，不会自动继承宿主机代理或转发到自定义连接。

更新代码后需要重新构建并重启相关服务，才能加载新路由、迁移和静态资源。
源码实现本身不自动更新正式部署；本地实例已按用户 2026-09-09 的部署指令更新，
具体镜像、备份和验证记录见 `docs/tasks.md`。升级前的备份／恢复步骤见
[数据库迁移](database-migrations.md#0030_model_settings)。

## 在设置页配置模型

页面顶部提供“MiniMax M3（国内官方）”预置。输入 MiniMax API Key 后选择
“配置并设为四阶段默认”，系统会通过既有浏览器加密信封将密钥只保存到 Gateway，
创建 `minimax` 连接与 `MiniMax-M3` Profile，并让机会分析、方案讨论、代码实现和
独立审查统一继承该默认 Profile。国内连接固定使用
`https://api.minimax.cn/v1`；不能把 NVIDIA 的 `minimaxai/minimax-m3` 模型 ID
或 `NVIDIA_API_KEY` 用于此连接。

1. 添加连接：名称、接口类型、Base URL、API Key。自定义地址形如
   `https://models.example.com/v1`；仅允许公共域名、HTTPS 443，拒绝本机／内网／
   metadata 地址、URL 凭证、查询参数和跳转。暂不支持本地 Ollama 或任意代理地址。
2. 添加模型：选择连接版本、填写服务商提供的完整模型 ID。可配置输出 Token 上限、
   单次调用超时、Temperature、推理强度和结构化响应。服务商／模型必须支持所选
   参数；不兼容时明确失败，不降级为 Fake。NVIDIA 和 MiniMax 保留工具调用
   结构化适配；MiniMax-M3 使用 adaptive thinking 和
   `max_completion_tokens`。
3. 点击“测试连接”验证一次最小结构化响应，不发送仓库上下文，可能产生服务商
   费用。测试是可取消的持久 Job；失败后可再次测试。“读取模型列表”需要服务商
   支持 `/models`，不支持时手动填 ID。用量不可获得时显示未知，不推算费用。
4. 设置默认模型，或为机会分析、方案讨论、代码实现、独立审查分别覆盖。
   两个阶段可使用同一模型，但实现和审查仍为独立调用、独立证据。

其他已保存 Profile 不会被删除，仍可作为手动备选。MiniMax 调用失败时只执行
同一 Job 的有界重试，不会静默改用其他供应商；手动切换任务模型会保留事件并使
依赖旧模型绑定的方案失效。已有任务和运行中的 Job 不会因启用新全局默认而重绑。

已有 NVIDIA 环境配置在首次启用管理接口时导入为非敏感配置版本；真实环境密钥
仍只在 Gateway。未配置管理密钥时，页面会说明原因，不允许假装保存 API Key。

### 版本与正在运行的任务

连接、模型、默认设置均追加版本，不能原地覆盖。修改连接（包括轮换密钥）后，
编辑模型选择新连接版本，再将默认／阶段选择指向新模型版本；旧绑定不会悄悄改变。
模型 Job 入队时绑定精确配置 ID/hash；贡献任务在首次消息时冻结四阶段配置。
全局设置只影响随后绑定的任务。

任务模型选择未变化时，“应用到此任务”禁用；API 重复应用相同四阶段版本也不会
创建模型配置版本或切换事件，返回 `changed=false`，并保留幂等确认记录。旧版已经
产生的重复切换记录只有在前后配置 hash 链和全部 profile ID 均可核实时才忽略，
历史记录不会删除或改写。真正切换、切换后再改回或无法证明的变更仍使旧方案失效；
重新保存会创建子方案，即使方案文字没改，也须重新批准。未应用的模型选择修改
会禁用执行按钮，避免显示选择与实际执行模型不一致。

已有任务可在空闲规划状态使用“本任务模型”修改阶段覆盖，或在输入框选择讨论
模型后发送消息。换模型会留下事件并使旧方案不能直接执行；重新生成或保存方案、
重新确认后才允许执行。运行中不能更改模型，也不会因另一页面保存设置而切换。

## 密钥安全与恢复

浏览器使用 WebCrypto RSA-OAEP + AES-GCM 封装 API Key，API 仅转发一次性加密
信封；Gateway 解封后用 AES-256-GCM 保存。业务数据库只保留不透明凭证引用。
相同信封的重试幂等，跨连接重放／修改信封被拒绝，保存后不回显密钥。

Gateway 私有目录权限为 `0700`，凭证数据库及密钥文件为 `0600`。私有卷包括
`credentials.sqlite3`、`master.key`、`envelope.pem`，必须作为敏感数据整体备份。
此设计隔离业务数据泄漏，不抵御已控制 Gateway 或能读取整个私有卷的攻击者。
新增 `cryptography>=43,<47` 仅用于成熟的 AEAD／RSA 原语，不自行实现加密算法，
无外部遥测；离线测试覆盖重开存储、篡改、重放、权限和凭证 canary。

不要删除旧凭证来“清理历史”；历史任务仍引用旧版本。丢失主密钥无法解密原凭证，
需重新录入并形成新连接／模型版本，不能伪造旧配置或修改执行绑定。

## 任务归档、恢复与删除

在任务工作台的“更多”菜单或贡献概览的任务列表中选择“归档任务”。
归档后任务从最近任务和默认列表移除；在贡献概览勾选“查看已归档任务”，
可以恢复任务，也可以确认删除。删除后没有恢复入口。

运行中或正在推进执行流程的任务需要先停止并等待结束，再归档。发布已确认、
远端结果尚未核对完成时，必须先核对发布结果。归档或删除不会触发远端写操作，
也不能通过旧页面、旧请求或 Job 重试继续处理；恢复后可以继续使用已有方案。
删除现在是永久删除：后台清理任务的计划、对话、执行、审查、发布记录、任务模型
选择、关联 Job、审计、归档记录和不再共享的文件，完成后也删除清理 Job 本身。
包含该任务的应用管理备份会一并删除，无法通过这些备份恢复。共享文件、发现阶段
的机会与分析、其他任务、全局模型配置和密钥保留。任务物理删除后可以从保留的
AnalysisVersion 重新创建任务。外部 GitHub 分支或 PR 不属于本地删除范围。

永久删除需等待其他后台工作空闲。清理状态在归档列表显示；失败可重试，已经
确认删除的任务不能恢复。按 2026-09-10 的用户明确要求，永久删除例外优先于
旧审计留存规则。未删除任务的审计不重写、不重算 hash；若全局链因删除出现
缺口，原验证器会如实报告无法验证，不能宣称历史链依然完整。

API：`GET /api/v1/tasks` 默认返回活动任务，`?archived=true` 返回归档任务；
`POST /api/v1/tasks/{id}/archive`、`POST /api/v1/tasks/{id}/restore` 和
`DELETE /api/v1/tasks/{id}` 均提交 `{"expected_sequence": N}`，其中 N 来自
任务列表的 `visibility_sequence`。首次归档 N 为 0，过期操作返回 409；重复
提交同一前序版本幂等。DELETE 返回 202 和 `job_id`；Job 存在时可轮询其状态，
成功清理后该 Job 也被物理删除，轮询返回 404。重复删除已不存在的任务返回
`state=deleted, job_id=null`。所有修改沿用本地令牌、Origin 和 CSRF 校验。

部署时先备份数据库和 Artifact，再重启升级到 `0031_task_visibility`，见
[迁移与恢复](database-migrations.md#0031_task_visibility)。浏览器验收脚本
`tests/task_visibility_browser.mjs` 仅对临时的 `tests.studio_browser_server`
执行归档、恢复和删除，不用于正式任务库。

## 验证与已知边界

默认测试不连接服务商、不使用真实凭证、不执行第三方仓库代码：

```sh
python -m pytest tests/test_model_settings.py tests/test_provider_jobs.py tests/test_workbench.py tests/test_migrations.py
python -m compileall -q app
git diff --check
```

可选浏览器验收：在一个终端运行 `python -m tests.studio_browser_server`，再在另一个
终端使用已安装的 Playwright 运行 `node tests/studio_browser.mjs`（必要时设置
`PLAYWRIGHT_MODULE` 为包的绝对路径）。服务监听 `127.0.0.1:8765`，每次使用新临时
数据库和假网关；不访问 `.env`、正式数据库或服务商。测试会在这个临时库保存模拟
连接，截图位于系统临时目录。结束后停止服务即可。

真实付费服务兼容性、真实模型到隔离执行再到审查的完整验收、真实 Draft PR 和
Linux amd64/Docker Engine 验收仍需相应环境；离线测试不能替代这些门禁。
